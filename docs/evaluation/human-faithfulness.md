结论：**34 通过 / 0 未通过**。自动关键词命中率 88.2% 与引用正确率 97.1% 的缺口，均可由下列四题解释，均非幻觉。

## 自动未命中但人工通过

- **Q04**（关键词否）：回答写「1,000个字符」，`rag_workflow.md` 原文即「按 1,000 个字符分块」。金标准词是 `1000`，千分位逗号造成自动假阴性，事实正确。
- **Q09**（关键词否）：回答写明 chunk ID 来自当前笔记本中 ready 来源、经余弦距离检索得到的前 5 个分块，与 `rag_workflow.md`「返回本次候选分块的 ID」一致。金标准含「候选;分块」，回答有「分块」而无「候选」，自动漏检。
- **Q32**（引用否、关键词否）：期望来源是 `demo_operations.md`（刷新后应再看到来源与会话历史），实际引用是 `api_contract.md`（刷新工作区应从持久化的 conversation 和 message 恢复历史）。两份语料都在讲会话/消息的持久化，属于来源级标注局限，不是编造。回答本身被所引 `api_contract.md` 支持，故通过。自动关键词「来源;会话历史」未出现，是因为模型用了契约里的英文实体名。
- **Q34**（关键词否）：回答「不会编造答案。」对应 `demo_operations.md`「也不应编造没有证据的答案」。金标准词是 `不应`，用词「不会」造成假阴性，约束本身成立。
