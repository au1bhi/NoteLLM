## 2.1 检索增强生成在本系统中的边界

RAG 在本课题里被收成四步：按笔记本取出 `ready` 来源的分块、用 1024 维嵌入做余弦近邻、把原文当作不可信证据交给聊天模型、服务端只保留本轮检索集合内的 chunk ID。默认 Top-K = 5，接口上限 10。相似度 `score = 1.0 - cosine_distance` 只用于排序，界面不得把它读成正确概率。

三种回答策略是服务端分支，不是提示词装饰：`grounded` 在无存活引用时改写为固定句且检索为空时不调用聊天模型；`hybrid` 允许无引用仍保留模型正文；`knowledge` 跳过检索、引用恒空。论文把它们当对照实验的自变量，未跑完不得写成「RAG 提高了准确率」。

本系统不做重排序器、混合检索、跨笔记本全局索引，也不做 NLI 式句子蕴含。评测里的「关键词命中」只是筛查，人工忠实度另表。

## 2.2 FastAPI 单体与 SSE

认证、上传、检索、流式问答和学习计划都在同一个 FastAPI 进程。流式接口 `POST /api/v1/conversations/{id}/messages/stream` 依次推送 `delta`、`citations`、`done`，失败推 `error`。这样前端可以边出字边挂引用，而不把模型密钥放到浏览器。OpenAPI 生成前端客户端；改过响应模型必须重新生成，避免手写 DTO 漂移。

独立 scheduler 进程只负责按计划时区在本地 09:00 投递已订阅提醒，不承担问答。学习计划表若尚未迁移，相关接口返回 503 而不是空白 500——`fastapi dev` 不会自动跑 Alembic。

## 2.3 PostgreSQL 与 pgvector

业务行与 1024 维向量同库。检索用 pgvector 的 `cosine_distance`，过滤条件是当前 `notebook_id`、来源 `ready`、向量非空。删除来源级联删分块和向量；删除笔记本级联会话与计划。测试和评测都必须另起隔离实例，不能打开发用的 Compose 5433 或本机 5432。

选用同库而不是独立向量服务，是为了让本科复现环境只维护一套 Docker Compose。论文应写这个取舍，不要写成「pgvector 优于专用向量库」。

## 2.4 文档提取与分块

TXT / Markdown 按 UTF-8（含 BOM）整文件读入；PDF 用 PyMuPDF 按页 `get_text("text")`，页码从 1 计。硬上限 `MAX_PDF_PAGES = 500`、`MAX_EXTRACTED_CHARS = 5_000_000` 挡住解压炸弹，与免费额度无关。默认分块 1 000 字符、重叠 150 字符；切点从窗口内 `CHUNK_MIN_BREAK = 500` 起优先换行再空格。评测脚本可以注入 `chunk_size` / `chunk_overlap`，上传 API 不暴露这两项，避免把消融旋钮做成产品功能。

不支持扫描件 OCR、复杂表格还原和图片理解。扫描 PDF 会变成空页或失败来源，论文里应如实写。

## 2.5 OpenAI 兼容调用与密钥位置

聊天和嵌入都走 OpenAI 兼容 HTTP。运营者把服务端地址写在环境变量；用户可选 BYOK，密钥用 Fernet 加密落库，读回只给掩码。浏览器既不持有供应商密钥，也不直接调用模型。用户 `base_url` 每次出站都要 DNS 解析、拒绝保留地址并 pin 到当时的公网 IP；运营者可选代理只给服务端模型用，用来避开 Fake-IP DNS 误伤，不能借给用户 URL。

## 2.6 前端与主题

界面是 React / Vite，中文文案，kraft/ink（牛皮纸 + 水墨）主题。工作区左侧资料、中间会话、右侧或抽屉里的引用与学习计划。侧边栏「甘特图」只聚合当前用户已有计划，生成入口在会话标题旁的「学习计划」。不要使用仓库 `img/` 里曾经放过的上游模板截图。
