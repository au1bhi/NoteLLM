## 6.1 实验目的

本章验证 NoteLLM 在固定合成语料上能否同时做到：（1）笔记本范围内召回期望来源；（2）服务端引用白名单使已验证引用落到标注文件；（3）关键词筛查能标出明显漏答，但不替代人工忠实度。实验回答的是「这套工程闭环是否可复现、可测量」，而不是「本方法在开放域 RAG 榜单上是否最优」。

对照实验（Top-K / 分块消融、三种回答模式）的协议与 CLI 已接通，结果表在 6.6、6.7 节留空，待本机隔离库实跑后抄入。不要覆盖本节引用的 2026-07-23 基线文件。

## 6.2 数据集

评测语料位于 `docs/evaluation/sources/`，共 **7** 份合成 Markdown，不含用户上传资料、账号、密钥或个人信息。内容是系统对自身工作流、评测规范、演示操作、接口契约、访问边界、产品范围与部署检查的说明，因此语料是**自描述**的：问题与答案都写在仓库里，检索目标短、措辞稳定。

固定问题集 `docs/evaluation/questions.csv` 共 **34** 题。每题指定一个期望来源文件和一组用于自动筛查的关键词。题型按协议分为三类：

| 类型 | 含义 | 示例 |
| --- | --- | --- |
| 事实定位 | 在指定文件中查找一个可核对的事实 | 默认分块长度、数据库镜像、嵌入维度 |
| 流程理解 | 还原处理或校验步骤 | 分块前先提取文本、未知引用 ID 的后端处理 |
| 边界条件 | 系统在证据不足或越权时的行为 | 资料不足固定句、跨用户 404、不得把密钥交给浏览器 |

本集合**不是**开放域问答基准，也不能外推到真实教材或长 PDF。

## 6.3 指标定义

下列定义逐句对应 `docs/evaluation/sources/study_protocol.md`，论文中不得改成 chunk 级命中、MRR 或 NLI 蕴含。

**Recall@5（来源级）。** 前 5 个返回分块中至少有一个来自该题**期望来源文件**，记为一次命中。Recall@5 = 命中题数 / 全部题数。这是文件名成员关系，不是「返回了含答案的那一个 chunk」，也不是排序质量指标。

**引用正确率（自动）。** 只在模型生成了回答时计算。若回答中**至少一个已验证引用**来自期望来源，记为正确。引用 ID 不在本轮检索候选集中的情况必须被后端丢弃，不能计入正确。换言之：引用正确 =「≥1 条经白名单验证、且来自标注期望文件的引用」。它不验证句子是否被摘录语义支持。

**关键词命中率。** 自动化忠实度**筛查**：回答是否包含该题指定关键词。回答包含关键词**不代表**人工审核已经通过，也不等于忠实度。关键词漏检同样不自动等于胡编——见 6.5 节 Q04 的千分位写法。

**响应时间。** 从开始调用检索到拿到检索结果、或从开始调用回答到拿到回答结果，以毫秒记录。报告使用**平均值和 P95**。网络波动、供应商限流和冷启动应在备注中说明。

**人工忠实度。** 最终由人工逐题阅读答案、已验证引用摘录与期望事实后确认。自动表不能替代该步骤。对应本次基线的复核已经完成：`latest-results.md` 的 34 行结论均为「通过」，归纳见 `docs/evaluation/human-faithfulness.md`。

## 6.5 自动指标与人工结论不一致的四题

自动表暴露了四题缺口。人工对照摘录后，四题均标「通过」，均非幻觉。不要把自动未命中写成「系统胡编」。

### 6.5.1 Q32：来源标签碰撞

- **问题**：刷新工作区后应保留哪两类内容？
- **标注期望来源**：`demo_operations.md`（「刷新笔记本工作区后，应能再次看到来源与会话历史。」）
- **自动结果**：Recall@5 = 是；引用来源匹配 = 否；关键词命中 = 否。
- **模型实际引用**：`api_contract.md`。该回答写的是应保留 conversation 与 message。
- **原因**：`demo_operations.md` 与 `api_contract.md` 都写了「刷新后从持久化数据恢复」。前者面向演示者，强调「来源与会话历史」；后者面向接口，强调 `conversation` 与 `message` 表。检索把两份都送进 Top-5（故召回来源级命中），模型引用了另一份语义相近的文件，自动引用正确率记失败；关键词「来源」「会话历史」也未出现，因为模型用了契约里的英文实体名。
- **人工结论**：通过。回答被所引 `api_contract.md` 支持，属于来源级标注局限，不是编造。

### 6.5.2 Q04：`1,000` 与 `1000` 的假阴性

- **问题**：默认分块长度是多少？
- **标注期望来源**：`rag_workflow.md`；期望关键词：`1000`。
- **自动结果**：Recall@5 = 是；引用来源匹配 = 是；关键词命中 = 否。
- **模型回答**：默认分块长度为 **1,000** 个字符。
- **原因**：千分位逗号使子串 `1000` 匹配失败。引用已指向正确文件，语义与语料一致。
- **人工结论**：通过。这是关键词筛查的假阴性，不是检索或引用失败。局限里应写明关键词匹配对数字格式敏感。

### 6.5.3 Q09 与 Q34：近义改写

Q09 正确说明 chunk ID 来自当前笔记本 ready 来源经余弦检索得到的前 5 个分块；金标准含「候选;分块」，回答有「分块」而无「候选」，自动漏检。Q34 写「不会编造答案」，对应 `demo_operations.md`「不应编造没有证据的答案」，金标准词是 `不应`。两题引用匹配均为「是」，人工均标通过。

## 6.9 局限（必写入论文正文）

本评测有几条硬边界，省略任何一条都会夸大结论。

第一，语料是**合成且自描述**的：7 篇短 Markdown 写的就是 NoteLLM 自己的说明，问题与答案同出一库，检索目标短、用词重复。Recall@5 = 100.0% 是这一集合上的**天花板**，不能当成开放域检索或真实教材场景的科学结论。

第二，Recall 是**来源文件名命中**，不是 chunk 级命中，也不是 MRR / nDCG。只要期望文件的任意分块进入 Top-5 即算命中，即使模型随后引用了另一份文件（Q32）。

第三，没有语义蕴含（NLI）或人工逐句对齐之外的自动忠实度模型。引用校验确认的是「ID 属于本轮候选、且来自期望文件名」；关键词命中只是子串筛查，会把 `1,000` 判成未命中（Q04）。二者都不等于「句子被摘录支持」。

第四，基线是**单次运行、单一嵌入供应商与单一聊天供应商、单一日期**的快照（2026-07-23，`cb0ead1`，embedding-3 + deepseek-v4-flash）。延迟受网络、限流和冷启动影响；不能外推为「本系统 P95 恒为 894 ms / 5595 ms」，更不能外推为「RAG 普遍优于无检索」。

第五，消融与模式对照的 CLI 已接通，但本仓库里这两张表仍是空的。空表不是阴性结果，也不能用 6.4 的旧提交数字去填新表。现场评测消耗真实 API 额度，必须在隔离数据库上跑，**不得进入 CI**。

## 6.10 复现方法

前置：已配置嵌入与聊天 provider 的本机或实验机；**独立**的 PostgreSQL + pgvector（不要用开发库或含用户上传的库）。脚本会创建临时评测用户、笔记本与来源副本，结束时删除用户、向量和文件。

```bash
# 在 backend/ 下。必须连隔离的 pgvector，不要用开发库端口冒充评测。
# 覆盖 latest-results.md 会改写已引用的 2026-07-23 基线，新跑写入 runs/。
uv run python scripts/evaluate_retrieval.py \
  --with-answers \
  --report ../docs/evaluation/runs/baseline-rerun.md
```

说明：

- `--with-answers` 会调用聊天模型，产生费用；只测检索时可去掉该开关。
- 消融：`--top-k {3,5,8}`；分块：`--chunk-size` / `--chunk-overlap`（已转发给 `process_source`）。
- 模式：`--mode {grounded,hybrid,knowledge}`。语料外：`--questions ../docs/evaluation/questions-ooc.csv`。
- 完整命令见 `docs/evaluation/ablation-protocol.md` 与 `answer-mode-protocol.md`。
- **不要把现场评测加进 GitHub Actions。** CI 使用假 provider 跑单元测试；真实评测是带密钥机器上的论文产物。
- 报告中不要写真实供应商端点、API 密钥或用户资料。需要占位 URL 时只用 RFC 2606 保留域。
- 评测脚本创建的临时用户邮箱使用 `example.invalid`，不要改成真实域名。

## 6.11 本章小结

在 7 份合成资料、34 个固定问题上，提交 `cb0ead1` 的单次基线为：来源级 Recall@5 100.0%，自动引用来源匹配 97.1%，关键词筛查 88.2%，检索 / 回答 P95 为 894 ms / 5595 ms。人工对照摘录后 34 题全部通过；自动缺口由 Q32 的来源标签碰撞与 Q04 / Q09 / Q34 的关键词假阴性解释，不是幻觉。消融与三种模式对照仍待本机在隔离库实跑填表。这些数字证明闭环可复现、可测量；它们不证明检索算法或生成质量达到研究前沿。
