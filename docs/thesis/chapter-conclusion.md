# 第 8 章　总结与展望（粘贴用草稿）

> 用法：回到工程闭环，不要改口成「提出了更优检索算法」。展望只写 MVP 边界内、作者本机就能做的下一步。消融表若仍是「—」，这里也不得写成已测。

## 8.1 工作总结

本文围绕个人学习场景，把「笔记本内检索、受控生成、服务端引用校验、会话级学习计划」做成一条可演示、可评测的链。

实现上，上传只接受 TXT / Markdown / PDF，按 1 000 / 150 分块后写入 1024 维 pgvector 索引；提问只在当前笔记本的 `ready` 来源上取余弦 Top-K；模型给出的 chunk ID 必须落在本轮检索集合。`grounded` 在无存活引用时改写为固定句「资料不足，无法根据当前笔记本中的来源可靠回答。」`hybrid` 与 `knowledge` 作为对照策略存在，不与默认路径混为一谈。学习计划从最近 30 条、至多 16 000 字的对话生成，周期钳在 3—60 天，提醒默认关闭且要求已验证邮箱。

安全上，笔记本范围内的对象按 `owner_id` 解析，不存在与无权限统一 404；用户 BYOK 地址与运营者代理分开；额度先原子预留再按实际结算；访问令牌、重置令牌和换邮令牌绑定改密时间。威胁模型承认：正文仍可能服从注入、任意公网主机都可当 BYOK 目标、`SECRET_KEY` 泄露可解密已存密钥。

评测上，7 份合成 Markdown、34 道固定题、提交 `cb0ead1` 的单次基线为：Recall@5 100.0%，自动引用来源匹配 97.1%，关键词筛查 88.2%，检索 P95 894 ms，回答 P95 5595 ms。人工对照摘录后 34 通过 / 0 未通过。Q04 / Q09 / Q34 是关键词假阴性，Q32 是来源级标注碰撞，均不是幻觉。100% 召回只说明这份自描述语料的天花板，不能外推到真实教材。

## 8.2 局限

合成语料短、措辞稳定、问题与答案都写在仓库里，来源级 Recall 容易饱和。关键词筛查会把「1,000」和「1000」判成漏答。三种回答模式和 Top-K / 分块消融的 CLI 已经接通，但数字格在本机实跑前必须留空。系统不做 OCR、表格理解和跨笔记本检索，扫描件与长教材不在结论范围内。安全回归是隔离库上的 pytest，不是渗透测试。
