# 第 1 章　绪论（粘贴用草稿）

> 用法：对着 `docs/project/GOAL.md` 写个人学习闭环，不要另写「大模型发展综述」。创新点按工程闭环完整性表述，不要声称检索或生成达到 SOTA。截图按 [`SCREENSHOTS.md`](SCREENSHOTS.md) 本机捕获。

## 1.1 研究背景

开放域聊天默认信任模型记忆。个人学习则先要回答三个更窄的问题：这句话还在不在我这份讲义里、出处能不能点开核对、今晚问完明天还知不知道该学哪一段。只做「先检索再生成」不够——界面上的引用卡片如果接受模型随口给出的 chunk ID，调用方仍然可能看到一段对不上原文的摘录。因此本课题把服务端白名单和弃权句算进主路径，而不是事后补的展示层。

本课题把范围收在单用户、单笔记本。资料只有 UTF-8 文本、Markdown 和可提取文本的 PDF。不做网页爬取、OCR、多人协作或独立向量库。这样答辩时能演示完整路径，而不是半套工业知识库。

## 1.2 研究定位与问题

NoteLLM 是毕业设计原型，不是产品对标。要证明的是：在笔记本范围内做余弦检索、服务端引用白名单、三种回答策略，以及把对话映射成 3—60 天学习计划，可以做成可演示、可评测、可复现的一条链。论文题目按仓库首页统一为「基于FastAPI与RAG的个人学习问答系统设计与实现」。

四个工程问题（不是榜单问题）：

1. 在当前笔记本的 `ready` 来源上取 Top-K 余弦近邻，回答能否带上可回看的来源名、页码和摘录。
2. 模型返回的 chunk ID 若不在本轮检索集合内，服务端丢弃之后，`grounded` 模式能否稳定落到固定句「资料不足，无法根据当前笔记本中的来源可靠回答。」
3. 从同一会话截取有限对话，模型给出的难度、周期和阶段任务，经后端范围校验后，能否覆盖 3—60 天且不越界。
4. 多用户共用同一套模型服务时，归属是否统一 404、免费额度是否原子预留—结算、用户填写的 BYOK 地址是否与运营者代理分开。

## 1.3 明确不做

对齐 `GOAL.md`，本文不覆盖：

- 多人实时协作、企业级 ACL、音频概览、移动端 App。
- 网页爬取、OCR、复杂表格 / 图片理解与全格式文档。
- 微服务、消息队列、多模型容灾、超大规模并发。
- 开放域检索 SOTA、语义蕴含（NLI）式忠实度判定、跨语料泛化结论。

这些不是「下一步必做」，写进展望会和正文自相矛盾。

## 1.4 本文工作

实现上，浏览器只走 HTTPS API 与 SSE；密钥和提示词留在 FastAPI；向量与业务数据同在 PostgreSQL + pgvector；上传文件落本地 Docker Volume。评测上，仓库提交 7 份合成 Markdown 和 34 道固定题，脚本在隔离临时用户上跑完即清理。安全上，跨用户对象返回 404，用户 URL 做出站固定，额度先预留再结算。

第 2 章只列实际用到的技术；第 3 章给架构与数据模型；第 4 章按 [`chapter-implementation.md`](chapter-implementation.md) 写摄取、检索、白名单与学习计划；第 5 章按 [`chapter-security.md`](chapter-security.md) 写边界与残余风险；第 6 章按 [`chapter-experiment.md`](chapter-experiment.md) 报告 2026-07-23 基线与已完成的人工复核；第 7 章写部署与复现；第 8 章按 [`chapter-conclusion.md`](chapter-conclusion.md) 收束。

## 1.5 创新点表述（可直接用于摘要）

本文的贡献是工程闭环，不是新检索公式：

1. 把「笔记本内检索—分角色提示—服务端引用白名单—三种回答策略」做成同一条可演示路径，并固定「资料不足」句，避免无证据时补造结论。
2. 把一次会话映射为校验过的 3—60 天学习计划，提醒默认关闭，且必须邮箱已验证才能打开。
3. 用公开合成评测集给出可复跑的 Recall@5、引用匹配、关键词筛查和时延；人工忠实度与自动指标分开报告，并解释四道自动未命中题为何仍通过。
4. 在多用户单体服务里同时落地归属 404、BYOK 出站固定、额度原子预留和改密作废令牌，威胁模型承认残余风险，不把绿测试写成渗透结论。
