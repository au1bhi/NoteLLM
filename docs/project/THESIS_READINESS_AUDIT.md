# 本科毕业论文完备性审计

审计日期：2026-08-13。审计对象为当前工作区的代码、测试、评测资料与 `docs/thesis/`
草稿。本文件判断的是“现有项目能否形成一篇可答辩的本科毕业论文”，不是把功能数量
当成论文质量。

## 结论

**项目功能已经足够，且总体功能量明显高于本科毕业设计的最低要求；不应再增加产品
模块。** 当前尚不能直接称为“论文终稿齐全”，缺口集中在实验实跑、截图、校内格式和
正文引用，而不是系统功能。

论文主线应收敛为一条可解释的闭环：

1. 笔记本隔离资料；
2. PDF / TXT / Markdown 提取、分块和向量化；
3. pgvector 余弦 Top-K 检索；
4. `grounded` 回答与服务端引用白名单；
5. 会话、引用和学习计划持久化；
6. 用固定问题集、消融和回答模式对照评估效果与边界。

这条链已经覆盖本科“需求分析—总体设计—数据库设计—关键实现—测试与实验—部署—
总结”的完整结构。学习计划是适量的应用扩展；其余工业化加固不应写成论文创新点。

## 本次补齐的最小功能

三种回答模式协议需要区分“引用率”“引用来源匹配率”“精确资料不足次数”和“无引用仍
作答次数”。原评测脚本只直接汇总引用来源匹配率与关键词命中率，模式实验需人工从逐题
表二次计数。

本次在 `backend/scripts/evaluate_retrieval.py` 增加以下报告项，并用离线单元测试覆盖：

- 引用率：至少保留一条服务端验证引用的回答数 / 全部回答数；
- 资料不足次数：只统计与固定弃权句完全相同的回答；
- 无引用仍作答次数：没有引用、且不是固定弃权句的回答数。

同时移除为旧版 `process_source` 保留的动态参数兼容层，改为调用当前显式接口；临时评测
用户补写当前数据模型要求的规范邮箱与邮箱历史，避免真实评测在入库前失败。

这是论文实验工具的必要补强，不增加数据库表、API、依赖或线上产品复杂度。

## 功能范围分级

### A. 论文核心：应重点讲清

- 笔记本与来源的用户隔离 CRUD；
- 三种文件解析、页码保留、字符分块与处理状态；
- 嵌入写入、笔记本范围过滤、余弦 Top-K；
- `grounded` 提示词边界、引用 ID 白名单与固定弃权；
- SSE 流式输出、消息和引用持久化；
- 固定评测集、人工忠实度复核和单变量实验方法。

这些模块算法难度适中、依赖成熟库、数据流清楚，符合本科生能够独立说明和实现的范围。

### B. 应用扩展：可以演示，正文少量说明

- `hybrid` / `knowledge` 两种对照模式；
- 笔记本概览、学习指南；
- 从对话生成 3—60 天学习计划与聚合甘特图；
- 会话标题、置顶、删除和新手引导。

这些功能能体现应用完整性，但不能替代 RAG 评测。学习计划只需讲结构化输出、范围校验和
持久化，不必把邮件调度当作主创新。

### C. 工业化加固：组合广度明显超出普通本科主线

- BYOK 密钥加密、OpenAI 兼容格式探测与切换冷却；
- DNS 固定的 SSRF 防护、IPv4 变体处理与运营者 Fake-IP 代理分流；
- 原子额度预留—结算、邮箱规范化、用量墓碑和重新注册继承；
- 目的限定令牌、改密撤销、邮件验证、防枚举和多层限流；
- 按时区 09:00 调度、数据库原子认领和失败重试；
- 低内存发布、CSP nonce、Cloudflare 注入兼容与生产管理面加固。

单项并非本科生绝对无法实现，但这些内容同时出现，已经接近生产运维与安全加固项目的
广度。若全部写成作者的核心研究贡献，会稀释 RAG 主线，也容易在答辩中产生无法深入解释
每个边界的风险。

处理方式不是删除现有代码，而是：

1. 冻结 C 类功能，不再扩张；
2. 正文只保留“密钥在后端、对象按属主隔离、上传文本不可信”三个直接相关边界；
3. 其余内容放在附录、工程实践或未来工作，并明确依赖成熟协议与库；
4. 答辩演示优先展示上传—检索—引用—重开会话—评测，不演示配额和邮件边角流程。

## 定稿前的硬缺口

以下事项不能靠新增产品功能替代：

1. 在隔离 pgvector 数据库与同一 provider 配置上实跑 Top-K `{3,5,8}`、分块
   `{500/50,1000/150,1500/200}`；默认交点只跑一次。
2. 在同一提交与配置上实跑 `grounded` / `hybrid` / `knowledge`，按新报告指标填表；
   语料外 6 题是推荐项，不是必需项。
3. 每轮保存配置、提交、日期、模型和异常，并逐题做人工复核。真实 provider 调用会产生
   费用，不进入 CI，也不能在未授权时由自动化流程代跑。
4. 按 `SCREENSHOTS.md` 从本人运行环境截图，不能拿仓库占位图或他人图片代替。
5. 把 Markdown 草稿改写进学校模板，补作者、导师、学院等真实信息；按学校格式加入文内
   引用并只保留正文实际引用的参考文献。
6. 在局限中保留“7 份自描述合成资料、34 题、来源级 Recall、单次 provider”边界；若时间
   允许，可再增加一组本人整理的课程资料作为外部效度补充，但这不是功能开发。

## 停止条件

完成上述实验、人工复核、截图和学校模板整理后，论文证据链即闭合。除非实验暴露核心
错误，否则不再新增模型、文档格式、向量数据库、协作权限、OCR、消息队列或移动端。
