# 答辩演示脚本（约 6 分钟）

## 演示前检查

不要对开发用的 Compose 5433 跑 pytest，也不要覆盖 `docs/evaluation/latest-results.md`。

```bash
docker compose up -d
cd backend
uv run alembic upgrade head
cd ..
```

本地打开 `http://localhost:5173`。生产环境没有 `/docs`。演示账户用 `docs/demo/` 与 `backend/scripts/seed_demo.py`，或当场注册。屏幕、终端和截图里不要出现 `.env`、真实邮箱、真实供应商地址或密钥。

## 讲解与操作

1. **目标（30 秒）**：这是单用户笔记本里的受控检索问答，不是开放域聊天。回答要能回到来源，一次会话还能长成 3—60 天学习计划。
2. **资料摄取（60 秒）**：创建笔记本，上传一份 UTF-8 TXT、Markdown 或 PDF，等到状态变成「已就绪」。PDF 引用带页码，TXT / Markdown 只带来源摘录。
3. **受控问答（90 秒）**：选「仅依据资料」，问一个资料里写明的事实。展示流式正文、来源名、页码（适用时）和摘录。强调模型给出的 chunk ID 必须落在本轮检索集合，未知 ID 会被丢掉。
4. **资料不足（30 秒）**：仍用「仅依据资料」，问语料外的问题。正文必须是固定句「资料不足，无法根据当前笔记本中的来源可靠回答。」不要把它讲成答错。
5. **学习计划（60 秒）**：在会话标题旁点「学习计划」生成 3—60 天任务。再打开侧边栏「甘特图」：这里只聚合，不会自己生成。空状态应能说明入口在会话里。
6. **隔离（30 秒）**：若准备了第二账户，用第一账户的笔记本 UUID 访问，界面或接口是 **404**，不是 403。
7. **评测（40 秒）**：打开已提交的 `docs/evaluation/latest-results.md`（2026-07-23，`cb0ead1`）。念 Recall@5、引用匹配、关键词筛查和 P95；补一句人工 34 通过 / 0 未通过，以及 100% 召回只是这份自描述语料的天花板。不要现场重跑 `--with-answers` 去覆盖该文件。

## 不要在现场执行的命令

评测脚本会打真实模型。需要对照口径时，翻 `docs/evaluation/runs/` 或已提交报告。若本机另跑，必须另起隔离 pgvector，报告写入 `runs/`，例如：

```bash
cd backend
uv run python scripts/evaluate_retrieval.py \
  --top-k 5 --mode grounded \
  --report ../docs/evaluation/runs/defense-scratch.md
```

## 常见问题的简短回答

- **为什么是 pgvector？** 本科复现只想维护一套 Compose，业务行和 1024 维向量同库即可；不是主张它优于专用向量库。
- **如何防止幻觉？** 不能写「已经防止」。能写的是：只提供本轮证据、引用 ID 走白名单、`grounded` 无存活引用则固定弃权。正文仍可能服从注入。
- **如何评估？** 固定 34 题可重跑来源级 Recall、引用匹配和时延；关键词是筛查。人工表已对该次基线标完，四道自动未命中题不是幻觉。
- **甘特图怎么生成？** `/gantt` 只读聚合接口。生成入口是会话上的「学习计划」。
- **下一步是什么？** 只填已留空的消融表和三种模式对照，不把 OCR、协作、微服务列成必做。
